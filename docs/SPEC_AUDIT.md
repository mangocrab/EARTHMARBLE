# 원본 명세 대조 점검 — 수정 전 기록 (2026-11-09)

> 아래는 수정 전 감사 기록입니다. 이후 처리 결과와 최신 검증은 [명세 누락 수정 및 검증](SPEC_RESOLUTION.md)을 보세요.

대상: [원본 개발 명세서](SPEC.ko.md), 현재 코드, 기존 규칙·서버·브라우저 테스트.

점검 당시 상태는 **핵심 게임은 실행되지만, 원본 명세의 모든 세부 항목을 충족한 최종 완성 상태는 아닙니다.** 이전의 테스트 50개·브라우저 4개 통과는 해당 테스트의 성공이며, 명세 전체의 완료 근거가 아닙니다.

이 기록을 작성한 작업은 명세 대조와 누락 확인이었으며, 아래 표는 수정 이전 상태를 설명합니다. 후속 수정은 별도 결과 문서에 기록했습니다.

## 실제 요청 재전송 재현

운영 DB와 분리한 임시 SQLite 및 별도 포트의 실제 서버에 Socket.IO로 연결해 확인했습니다. 테스트용 세션만 사용했고 임시 서버·DB는 종료·정리했습니다.

1. 최대 4명·AI 허용 방 생성.
2. `{type:'ai', difficulty:'normal', requestId:'ai-once', version:0}`을 동일하게 두 번 전송.
3. 두 응답 모두 `ok:true`. 참가자 수는 2명 → 3명으로 증가.
4. `{type:'ready', requestId:'ready-once', version:0}`을 동일하게 두 번 전송.
5. 준비 상태는 `true` → `false`로 다시 변경.
6. 공개 대기실 상태에는 방 버전 필드가 없음.

따라서 이는 코드만 보고 추정한 문제가 아니라 실제 재전송으로 재현된 누락입니다. 기존 게임 행동의 중복 요청 방지 테스트가 대기실 행동까지 검증하는 것은 아닙니다.

## 구현은 있으나 검증이 충분하지 않은 항목

- **탐사 카드 30장의 개별 효과**: 전체 카드를 순회하는 테스트는 카드 총수·마지막 카드 ID를 확인합니다. 모든 카드의 지급액·이동 목적지·유지비·구조조정 매각 우선순위를 각각 검증하지는 않습니다. 일부 효과만 별도 테스트가 있습니다.
- **90초 재접속 경계**: 즉시 재접속·서버 재시작 복구는 테스트했지만, 실제 유예 경계 전후와 자동 행동 인계·복귀는 별도 테스트가 없습니다.
- **재접속 후 덱 순서·보관 카드·미완료 통행료 정산**: SQLite에 상태 전체를 저장하는 경로는 있으나 통합 테스트의 복구 비교는 주로 플레이어·주사위·버전입니다. 각 경계 상태의 중복 추첨/지급 방지를 모두 검증했다고 할 수 없습니다.
- **3·4인 자동 매칭**: 2인 자동 매칭·취소와 4인 개인 방 시작은 테스트합니다. 3/4인 자동 매칭, 네 명이 모여도 10초 종료까지 기다리는 경계, 다중 매칭 그룹은 별도 테스트가 없습니다.
- **소유지 동기화 UI**: 뒤집기·과학 설명 조회는 브라우저 테스트가 있지만, 카드가 열린 동안 다른 클라이언트의 건설·매각·파산으로 정보와 소유자 색상이 바뀌는 경우는 전용 브라우저 테스트가 없습니다.
- **주사위 최종 윗면**: quaternion으로 서버 눈의 면을 위로 정렬하는 코드가 있습니다. 1~6 각 면의 최종 방향을 확인하는 독립 테스트는 없습니다. 기존 브라우저 테스트는 주로 게임 진행과 대체 주사위를 검증합니다.
- **외부 인증 어댑터**: 인터페이스·로딩·프로필 UI는 있으나 테스트 어댑터를 이용한 통합 테스트와 실제 사이트 연동 검증은 없습니다. 특정 사이트 연동에는 해당 사이트 인증 계약이 필요합니다.
- **모바일 가로 모드**: 터치 브라우저 테스트는 390×844 세로 화면입니다. 명세의 가로 우선 화면과 실제 모바일 기기·Safari/Firefox는 검증하지 않았습니다.
